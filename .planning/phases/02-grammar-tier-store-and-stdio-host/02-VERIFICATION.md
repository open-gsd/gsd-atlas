### Criterion 4 re-check (STO-05)

What I did: read `scripts/size-gate.ts` in full, then ran it.

- Header and code agree. `runSizeGate` runs `edited.maintain(MAINTAIN_BUDGET_MS, idle)` every 200 edits with `idle = options.idle ?? IDLE_MAINTENANCE` (the same constant `src/tenant/create.ts` `maintenanceSlice` passes), then settles with more `maintain` calls, then reads `idleBytes = (await edited.status()).sizeBytes` (line 263) **before** `settledSize(edited)` runs the explicit `compact({ full: true })` (line 265). `ratio = idleBytes / freshBytes` and `ok: ratio <= maxRatio`. The explicit-compaction figure is only printed as `settledBytes` / `settledRatio`. So the gate asserts the idle-only size.
- Product path is the same policy, not a test-only one: `IDLE_MAINTENANCE = Object.freeze({ full: true })` (`src/fact-store/maintain.ts`); `maintainStore` passes `full: true, afterChurn` to compact only when collect completed; `compactStore` (`src/fact-store/lifecycle.ts`) vacuums when free pages exceed a quarter of the file or `dbstat` unused bytes exceed a third (`FRAGMENTED_FRACTION`), and decides a second time after the incremental slices (`worthVacuuming(db, 0, afterChurn)`); the Tenant's `idleRound` calls it. The fallback without `dbstat` is `afterChurn`.
- Runs (macOS arm64, Node 26): `node scripts/size-gate.ts` exit 0, `idleRatio 1.0000`; `--driver better-sqlite3` exit 0, `idleRatio 1.0000` (longest maintain 206 ms: a full VACUUM); negative control `--maintain-every 0` exits 1, `idleRatio 38.2687 OVER`, so the gate can still fail. Previous policy measured 1.396.
- Caveats, none blocking: (a) the gate commits with `gitHas: async () => true`, so collection is immediate; in production a retired version waits for its blob in git or for `graceMs`, so the real ratio during a long uncommitted editing session depends on the grace period. (b) The gate vacuums in 100 of 101 maintenance runs because each run follows 200 edits across 300 files; the comment's "keeps the idle loop from vacuuming every round" holds for a quiet store (`src/tenant/idle-compaction.test.ts` "healthy store is left alone"), not for this synthetic churn. (c) A full VACUUM is a single unsliced pause (measured 14 to 24 ms for node:sqlite and 206 ms for better-sqlite3 on a 650 KB store; 608 ms on hosted Windows); on a real 37 MB store it will be longer. This is the owner-approved exception to `maintenance.sliceMs` (02-CONSTANTS.md addendum, ADR 11 amendment 2026-10-17).
