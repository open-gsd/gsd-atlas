## Artifacts this phase produces (plan 02-08)

- `GrammarLockSchema` upstream source gains optional `generate: boolean` (default true when absent). `serializeLock` writes it after `subdir`.
- `buildWasm(cliBinary, workDir, outFile, options?)` gains `{ generate?: boolean }`; with `generate: false` it runs only `build --wasm`. A pure helper `buildCommands(options)` returns the CLI argument lists so the behaviour is testable without the wasi toolchain.
- `modules/typescript/` and `modules/javascript/`: `atlas-lang.json` (schemaVersion 1, name, version 0.1.0, extensions, grammar {wasm: grammar.wasm, lock: grammar.lock}, queries {tags: queries/tags.scm}, tiers [grammar], parseBudget 0.005), `grammar.lock`, `grammar.wasm`, `queries/tags.scm`, `fixtures/basic.ts` or `fixtures/basic.cjs` and its golden.
- `scripts/module-goldens.ts`: `node scripts/module-goldens.ts <moduleDir> [--check]` writes (or with `--check` compares) `<fixture>.golden.json` for every fixture the manifest's extensions claim, using the real engine, `renderGolden` and `serializeGolden`.
- `scripts/corpus-fetch.ts`: `fetchCorpus({ id, destination, remote? })` returning `{ dir, sha }`; `node scripts/corpus-fetch.ts <id> [--dest <dir>]` prints the directory. `remote` overrides the base URL for tests.
- Deferred, recorded here: `.tsx` support (a data-only `tsx` module from the same archive, `subdir: tsx`) is not built in Phase 2 (user decision 1).
