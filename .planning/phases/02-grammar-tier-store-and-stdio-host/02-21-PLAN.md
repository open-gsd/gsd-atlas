<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| init to user configuration files | The command edits files that control which programs an agent host launches. |
| current directory (possibly a hostile repository) to init | A repository could try to make init write into it or follow its links. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-02-72 | Tampering | clobbering or corrupting a user's host configuration | high | mitigate | Parse before writing; refuse unparseable input byte-identical; preserve all other keys and text; atomic rename; one-time backup; tests for each refusal and for preservation (prohibitions above). |
| T-02-73 | Elevation of Privilege | registration written into repository-level config (MCPoison class) | high | mitigate | Paths are derived only from the injected home directory; no cwd-relative path is ever written; test asserts the working repository is unchanged. |
| T-02-74 | Elevation of Privilege | registering an untrusted launch command | medium | mitigate | The command is the node executable plus the absolute path of the installed gsd-atlas-mcp entry supplied by the bin, never a PATH lookup or user-supplied string; init takes no free-form command argument. |
| T-02-75 | Tampering | symlink swap between check and write | low | accept | Single-user local file operations; the write resolves the real path once and renames within that directory. |
| T-02-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed by this plan; no TOML library is added (text edit only). |
</threat_model>
