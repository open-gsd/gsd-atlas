<objective>
Give the Fact Store its lifecycle skin: where it lives (git common dir with cache fallback and override), who may write (the cross-process writer lease and followers), and what happens when it breaks (dirty sentinel, quick_check, quarantine and rebuild, schema-version policy).

Phase goal (ROADMAP.md, quoted verbatim): "A developer can build a local fact index of gsd-core on macOS, Linux or Windows and ask cited, fresh, worktree-correct questions (find, refs, context, impact) through the CLI or a stateless stdio MCP server."

Purpose: STO-06, STO-07, STO-08; D-14, D-15; research Patterns 3 and 4; the worktree-lifecycle and sqlite-store amendments from plan 02-01.
Output: `location.ts`, `lease.ts`, `recovery.ts`, extended `open.ts` and `store.ts`, and three test files plus two child-process helpers.
</objective>

<assumption_delta_decision>
Signal: a second session (process) on one repository, and a cache-directory fallback for the store location.
Primary noun: the store (storeId, one per repository) as the unit of write exclusivity, with the worktree overlay as the unit of visibility; a session or process has no identity in the data model (pid and start time exist only as lease diagnostics).
Decision: no-change. Overlays per worktree and a per-store lease already name the right nouns; the follower is a reader of the same store, not a second copy. Invariant test: reads through a follower equal reads through the leader except for the degraded field (asserted in plans 02-12, 02-20 and 02-25).
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository to store location | A hostile repo could plant a symlink at .git/gsd-atlas or try to influence the path through its own config. |
| store directory to other local processes | Files in the git common dir or cache dir are readable by the user's other processes. |
| corrupt database file | Bytes on disk that SQLite may fail to read. |
