    - "D-03: a follower (a process that does not hold the writer lease) never writes. For a request with `fresh` paths it parses those paths into an in-memory overlay for that request only, merges the overlay over the shared store facts, and answers with degraded follower; no message is sent to the leader and nothing is cached across requests."
    - "The overlay Reader implements the whole Reader interface by merging: find, symbol and fileFacts take the patched file's facts instead of the store's for patched paths (a deleted or unreadable path hides the store's facts for it); refs drop store sites that sit in patched files and add the patched files' sites that are in scope (same file as the target, or an import binding that resolves to the target's file and imported name); callers and importers are derived from the merged refs and imports; every added record carries the same provenance shape as store records (extractor string, content hash from the patch, first_seen and last_seen from the Clock, EXTRACTED for definitions and INFERRED for references)."

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent-supplied `fresh` paths to file reads in a follower | The same path validation concern as the leader's ensureFresh. |
| in-memory overlay to answers | Merged data must not leak between requests or tenants. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-02-84 | Information Disclosure | path traversal and symlink escape through `fresh` in a follower | high | mitigate | The same validation as plan 02-15 (absolute, dot-dot, NUL rejected; realpath containment), tested in overlay.test.ts; rejected paths are never read. |
| T-02-85 | Tampering | a follower corrupting the shared store | high | mitigate | The overlay module has no Writer access and no database handle (acceptance check); the untouched-store test compares sizes and times of every store file. |
| T-02-86 | Information Disclosure | an overlay surviving into another request | medium | mitigate | The overlay reader is constructed per request inside the fresh port and dropped with the request; a test checks the next request does not see it. |
| T-02-87 | Denial of Service | a request listing many large fresh paths | low | mitigate | Per-file byte cap (the source cap), the Governor fresh slot per request, and the ensureFresh wait bound. |
| T-02-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed by this plan. |
</threat_model>
