<objective>
Make `gsd-atlas init` explain a rename that the operating system refuses, and make its concurrency test deterministic on every OS.

Phase goal (ROADMAP.md, quoted verbatim): "A developer can build a local fact index of gsd-core on macOS, Linux or Windows and ask cited, fresh, worktree-correct questions (find, refs, context, impact) through the CLI or a stateless stdio MCP server."

Purpose: HST-04 and WR-12. Plan 02-35 made `init` refuse to overwrite a config another program changed while init ran. On Windows a rename onto a file that another handle holds open for a moment fails with EPERM, which init reported as a bare `could not write the file`. The user cannot tell that nothing was changed and that running init again is the remedy, and the test that races two inits fails on hosted Windows.
Output: a `config_in_use` refusal with a message that says what happened and what to do, scripted-fs tests that cover the Windows errors on every OS, and a concurrency test whose acceptance set is exactly the legitimate outcomes.

Both predecessor plans (02-35 and 02-44) are executed and merged; this plan is the first wave of the remaining work, which is why it is wave 1 although its dependencies are listed.
</objective>

<interfaces>
`writeUserFile(p, nextText, { bom, expected, afterTemp? })`: resolves the target, compares it with `expected` (first compare), copies the one-time backup with `COPYFILE_EXCL`, writes a temp file beside the target (`wx`), calls `afterTemp`, compares again, then `rename(temp, target)`; a failure in that block removes the temp file and rethrows, and a backup made earlier stays. `ConfigChangedError` (`code` `config_changed_during_init`) is thrown by a compare. `registerWith` in `init.ts` calls `env.beforeWrite`, then `writeUserFile`, and maps `ConfigChangedError` to a refusal whose reason starts `config_changed_during_init:`; any other error becomes `could not write the file: <message>`. A refusal makes the host result `refused`, prints `gsd-atlas: init <agent>: refused <file>: <reason>` on stderr, adds a `config_refused` diagnostic and exits 2. `InitEnvironment` carries the TEST ONLY hooks `beforeWrite` and `afterTemp`; `src/cli/init.test.ts` has a rig whose `run(argv, options)` forwards them, the constants `REASON` (a regular expression for the `config_changed_during_init` prefix), `CLAUDE_ENTRY`, `ORIGINAL_CONFIG`, `BACKUP`, and the helper `seedClaude`.
Windows facts this plan relies on: a rename onto a file that another process (here, the other racing init reading it) holds open fails with `EPERM` (sometimes `EBUSY`, and `EACCES` for permission problems); Node's rename does not retry.
</interfaces>
