<objective>
Close verification gap CR-02 (01-VERIFICATION.md `gaps` first entry; 01-REVIEW.md CR-02): a filter driver whose name contains `=` is never neutralised, because `parseFilterNames` cuts each `--name-only` line at the first `=` and drops the key, and because a `-c filter.<name>.clean=` pair cannot carry an `=` in the name (git splits `-c` at the first `=`). `SourceTree.snapshot()` then runs the repo-controlled clean command during `hash-object --stdin-paths`. Move all driver neutralisation to the `GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_n` / `GIT_CONFIG_VALUE_n` environment channel (any name is expressible), parse names without splitting on `=`, make `decide` validate that channel strictly, and make driver enumeration fail closed with a per-call probe so an older git that ignores the channel can never silently skip neutralisation.

Phase goal (ROADMAP.md, quoted verbatim): "A developer can build and test the repo on macOS, Linux and Windows and run `gsd-atlas lang test` on a fixture language module end to end, with every module seam frozen behind an interface and a test double."

Purpose: FND-05 and FND-06, ROADMAP success criterion 4, D-10 and D-11. Plan 01-13 promised "no allowlist, every driver"; this plan makes the promise hold for every name git can store. It builds on plan 01-18 (the lazy-fetch pins and the decide requirement for overrides and pinned env), which must be merged first because both plans edit `git-spec.ts`, `decide.ts` and `hostile-repo.test.ts`.

Explicitly out of scope: the option-parser items of review finding WR-01, WR-02 to WR-05 (Source Tree correctness), the editorial and confirmation items listed under `human_verification` in 01-VERIFICATION.md (ADR repairs, the truncated SDK-PROVIDERS clause, the 60 s and 5000 ms default timeouts, the PR-event CI run, the Fact Store seam judgment). Those are human decisions and are not tasks.

Known risk to confirm in CI: the empty-string value of `GIT_CONFIG_VALUE_n` must survive process creation on Windows. If git for Windows treats an empty environment value as missing, git exits non-zero ("missing config value"), the probe read fails, and the snapshot throws. That is a loud failure, never a silent bypass; the three-OS CI run after this plan is the proof, and the SUMMARY must say it is pending.
