## Artifacts this phase produces (plan 01-14)

- Types: `LangTestReport` {ok, module, fixtures: [{file, ok}], diagnostics}.
- Functions: `runLangTest({ target, engine })`; `renderGolden(fixture, runResult)`; `compareGolden(expected, actual)`; `createInProcessHostClient({ engine })`; `runCli(argv, io)`.
- Request kind: `lang_test` (args `{target}`); envelope schema `gsd-atlas.lang-test/1`; extra diagnostics `unknown_kind`, `unsupported_protocol`, `module_not_found`.
- CLI: `gsd-atlas --version|-v|--help|-h`; `gsd-atlas lang test <module-folder>`. The target is a directory path (absolute, or relative to the working directory). Any other flag is a usage error (exit 1). Defaults in the composition root: engine from `createGrammarEngine()`.
- Diagnostic codes: `golden_missing`, `golden_mismatch`, `fixture_unreadable`, `module_not_found`, plus those from earlier plans.
- Golden file shape: `{ schema: 1, fixture, convention, hadBom, captures: [{query, name, startLine, startColumn, endLine, endColumn, text}] }` where convention is the text `0-based line, 0-based UTF-16 column, end exclusive`.
- Exit codes: 0 ok; 1 usage error or a target that is not an existing module folder; 2 any other failure.
- Extension point for plan 01-17: the target rule in `runLangTest` is one function with a single branch for "not an existing directory"; plan 01-17 adds the registry lookup by id in that branch, a `roots` parameter, the four root flags, the default roots in the composition root and the `lang_list` request kind.
