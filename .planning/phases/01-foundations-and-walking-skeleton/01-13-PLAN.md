<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository .git/config and .gitattributes to git subprocesses | Both are repo-controlled and can name commands that git runs. |
| repository path names to the hash batch | Newlines and options-like names can corrupt a line-oriented batch. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-01-32 | Elevation of Privilege | filter.<name>.clean/smudge/process executed by hash-object | high | mitigate | Enumerate all driver names and neutralise every one (no allowlist); gitSpec is the only way to build git commands; hostile-repo test with positive control. |
| T-01-33 | Elevation of Privilege | core.fsmonitor and core.hooksPath commands | high | mitigate | -c overrides on every git command; subcommand allowlist excludes status; hostile-repo test. |
| T-01-34 | Tampering | newline-containing or option-like path names misattributing hashes or injecting options | medium | mitigate | Newline and carriage-return paths skipped with unhashable_path; one output id per input line verified; hash and commit arguments validated before use. |
| T-01-35 | Denial of Service | git prompting for credentials or contending for index locks | low | mitigate | GIT_TERMINAL_PROMPT=0 and GIT_OPTIONAL_LOCKS=0 in every spec; timeouts from the runner. |
</threat_model>
