<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| module folder contents to the host | A language module (repo, user or npm) is untrusted data: manifest, wasm bytes, query text, symlinks. |
| WASM linear memory | Grammar code runs sandboxed inside web-tree-sitter; its objects live in WASM memory until deleted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-01-29 | Tampering | malformed, oversized or hash-mismatched wasm and queries | high | mitigate | Size caps, sha256 check before instantiation, typed load errors, realpath containment and symlink rejection in module-files; never crashes the caller. |
| T-01-30 | Denial of Service | a hostile query using a regex predicate that backtracks catastrophically | medium | accept | Phase 1 runs only modules the developer chose explicitly, with query files capped at 256 KiB; per-parse time limits through the parser progress callback arrive with the Phase 2 worker. The risk and the deadline are recorded here. |
| T-01-31 | Denial of Service | WASM objects never released, so memory grows for the life of a daemon | medium | mitigate | All parsing through withTree with deletion in finally, cursor deletion in measure, one Parser per loaded grammar disposed on dispose, lint rule against parse calls elsewhere, leak tests. |
</threat_model>
