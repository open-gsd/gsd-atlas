## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host process to the compiler child | The child executes JavaScript from the repository (the project's own TypeScript) when the project has 6.x. |
| worker output to the store | Edges, positions and paths come from a process running repository-influenced code. |
| manifest and user config to tier creation | Only the user can turn the built-in tier off; no repository file can add one. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-231 | Elevation of Privilege | repository-supplied compiler JavaScript running in the worker (D-13, ADR 4 decision 5) | high | mitigate | Loaded only in the killable child, minimal environment (a test prints it), no secrets passed, location sent as data, `createProgram` only (no plugins, no language service), tsconfig plugins never loaded; residual risk accepted by the recorded decision and documented in the trust-boundaries amendment. |
| T-03-233 | Denial of Service | out-of-memory, hang or crash of the worker | medium | mitigate | Heap flag from the budget, exit mapping to `memory_budget`, request and start timeouts from the approved constants, restart once per read, kill on close and on parent death. |
| T-03-234 | Information Disclosure | repository text in diagnostics or envelopes | medium | mitigate | Fixed-text diagnostics for every fallback; the worker's stderr is never forwarded; positions and names go through the store like any fact. |
| T-03-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no package; typescript 6.0.3 came in under plan 03-02's blocking-human approval. |
</threat_model>
