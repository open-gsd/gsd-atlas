<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| module manifest to a process start | A manifest proposes a command; only user-level config can make the runner start it. |
| command output to the answer stream | Output of a third-party command is untrusted and must not enter envelopes, metrics or logs. |
| eager pass to resources | A large repository makes the eager pass long. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-03-291 | Elevation of Privilege | a repository running its command without approval | critical | mitigate | Runner `decide` with exact hashed entries; unapproved is not started and reports `needs_approval`; hostile-repository test unchanged; changed argument test. |
| T-03-292 | Information Disclosure / injection | command output reaching envelopes or storage | high | mitigate | The helper never reads stdout or stderr; a marker-string test greps envelope, recorder and metrics. |
| T-03-293 | Denial of Service | a command or the eager pass running unbounded | medium | mitigate | The command uses the approved `precise.requestTimeoutMs`; the eager pass is time-boxed and resumable; builds stay successful with a timeout note. |
| T-03-294 | Tampering | stale cache after edits | medium | mitigate | Edges are keyed by overlay snapshot and context; the update message keeps the worker in step; tests edit and re-ask. |
| T-03-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no package. |
