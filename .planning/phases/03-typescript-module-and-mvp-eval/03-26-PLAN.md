<objective>
Let an agent or a developer ask why atlas said something, at the Query level first: which extractor, tier, grammar version, resolution context and overlay a fact came from, and which compiler resolved it. This part builds handle parsing, the store's provenance function, `query.explain` and the explanation for every kind of fact and for answer ids. The shared tool table is untouched here; plan 03-50 registers `code_explain` and `gsd-atlas explain` everywhere at once, after plan 03-49 makes the tool-count assertions table-derived.

Phase goal (ROADMAP.md, quoted verbatim): "A developer working on gsd-core gets compiler-precise, cited answers (callers, implementers, `.cts` to `.cjs` emit mapping, ADR citations) with `explain`, and agents using atlas consume fewer tokens than a grep-only baseline at non-inferior accuracy."

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-261 | Tampering | crafted handles reaching outside the overlay or causing odd queries | high | mitigate | Strict parse (shape, length, hash form, no `..`), lookups by (path, hash, ordinal) inside the overlay snapshot with bound parameters; fuzz test. |
| T-03-262 | Spoofing / injection | repository text steering an agent through the explanation | high | mitigate | Free-text fields are fixed sentences; names appear only as field values; test with an instruction-shaped identifier. |
| T-03-263 | Information Disclosure | the explanation leaking absolute paths | low | mitigate | Only repository-relative paths and the worktree's base name are returned. |

</threat_model>
