## Interpretation rules (fixed before any replication data exists)

These rules are implemented in `scripts/cleanroom/compare.ts` and tested in Task 1, committed before Task 3, and quoted unchanged by the report. Task 9 fails if `compare.ts` or its tests changed after the commit recorded in the progress file, unless the human approved a new rule set before the run began.

Standing statement. The registered verdict is `OVERALL: MVP not met` in `docs/eval/analysis.md`. A replication cannot make the MVP met, cannot make it not met, and cannot unblock Phase 4. Only a new registered run that meets the gate does (D-04).

Compared quantities (original O against replication R, same 75 questions, same 450 cells):
- S1 accuracy difference: per question, the atlas run-mean correctness minus the grep run-mean correctness (`isCorrect` of the registered analysis: a session not `ok` counts as incorrect). O: +0.0489, 5th percentile +0.0133.
- S2 token difference: per question, the atlas mean billable tokens minus the grep mean. O: +17,982.0, 5th to 95th percentile +15,435.1 to +20,709.4. The token ratio atlas over grep (O: 47,375.1 over 29,393.1, 1.612) is reported beside it.
- S3 atlas citation rate: the share of atlas sessions on the 66 non-abstain questions whose answer has a verifiable citation (`isVerifiable`). O: 144 of 198, 72.7 percent.
- Reported, not classified: the grep citation rate (O 146 of 198), the share of atlas sessions that called an atlas tool (O 86 of 225, 38.2 percent), sessions that loaded the skill (O 0 of 225), notional cost (O 16.1142 USD), mean wall time (O 7,910 ms atlas, 7,627 ms grep), failed sessions (O 0), per-category accuracy and token ratio, and the cell-level flips between O and R per arm (the noise floor).

Validity (evaluated first). `invalid` when any of: fewer or more than 450 rows, a cell outside the registered set or a duplicate; a `contaminated` or `prep_failed` record; an init signature that differs from the registered one for its arm; a hook event in any stream; an infrastructure-class finding left in the kept data; `isUsingOverage` or `overageEnabled` true in any stream; a session that touched the credentials file; a question set that differs from the registered one. `degraded` when the data is otherwise valid but at least one session ended with a status other than `ok`. Neither class is interpreted; the report states the cause and the numbers.

A1, criterion agreement. For H1, H2 and H3, the met or not-met outcome under the registered rule and the registered parameters (computed for both runs by the registered analysis code from the frozen block): agree when R's outcome equals O's (O: H1 met, H2 not met, H3 not met; overall not met).

A2, compatibility. For each of S1, S2 and S3, the per-question between-run difference d(q) = S(R, q) minus S(O, q) is bootstrapped over questions (`bootstrapDistribution` of the registered stats module, 10,000 resamples, seed 20261017, percentile rule at 0.025 and 0.975); the statistic is compatible when the interval contains zero. The questions are the same in both runs, so the question effect cancels and what remains is run-to-run and environment variation. Under pure noise each statistic is flagged about once in twenty times.

Classes. `strong-agreement`: valid, every A1 agrees, every A2 compatible. `agreement-with-drift`: valid, every A1 agrees, at least one A2 incompatible; the report names the statistic, the difference and the interval. `disagreement`: valid and at least one A1 differs. `inconclusive`: invalid or degraded.

What each class triggers. strong-agreement: the report says that, within the limits below, the registered result did not depend on the maintainer's machine or configuration, and Task 10 offers the registered verdict as the default. agreement-with-drift: the report names what moved; Task 10 is informational. disagreement: a human review is required at Task 10 before the plan ends; the options are `accept-registered` (the registered verdict stands and the replication is recorded as unexplained environment sensitivity), `diagnose` (a follow-up diagnosis, outside this plan, from the raw streams kept on the maintainer machine) and `new-run` (a new registered run through the Deviations policy with its own approvals; this plan changes nothing). inconclusive: no interpretive claim; Task 10 offers `accept-as-reported` or `rerun-clean` (a new execution of this plan with a fresh results directory after the cause is fixed).

Declared differences (user decision 2026-10-18, fixed before any replication data exists). The clean room is not the same machine, and the design says so in advance. It differs from the original run in: the Node version (original run 26.11.1 on the maintainer machine, which the run did not record; clean room 24.22.0 by default, or 26.12.0 if `node=26.12.0` is approved at Task 3), the operating system and architecture (macOS arm64 against Debian bookworm x64), the CPU and memory limits, the user-level configuration (the maintainer's account state against one neutral notes file), the network location and the time. These are the conditions under test, not confounds to hide or to adjust away: `compare.ts` lists them in its output (`DECLARED_DIFFERENCES`), the report puts the Node version in its side-by-side table, and neither the classes nor any number is corrected for them. Consequence for reading: `strong-agreement` says the registered result did not depend on these conditions taken together; `agreement-with-drift` and `disagreement` say the result differs under these declared conditions and do not isolate which one caused it. Attributing a difference to the Node version in particular (24 against 26) is outside this plan (`diagnose`, or a second execution of this plan with `node=26.12.0`); the rules never decide it and the report never asserts it.

Limits stated in the report: one replication; the same account, the same model alias (the served model may change between the two dates and the harness records only the alias), the same 75 questions and keys, one machine class, one time window; agreement does not show that the result generalises to other repositories, models or users, and says nothing about the quality of the atlas tools beyond the measured quantities.
