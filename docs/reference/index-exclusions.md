# gsd-atlas index exclusions reference

What the index leaves out, and how to leave out more. The commands are in [the CLI reference](cli.md), the shape of the status answer in [the MCP reference](mcp.md). To exclude files in your own repository, see [How to exclude files from the index](../how-to/exclude-files-from-the-index.md).

## What the index holds

The index holds the files that git lists for the repository (tracked files, plus untracked files that git does not ignore), less the built-in paths below, less the files a `.atlasignore` names. The other rules of what counts as source (a claimed extension, not generated or vendored, not binary, not over the size cap) apply after that. Only the set of indexed files changes: nothing is deleted from disk, and the TypeScript compiler still resolves types from `node_modules`.

## Built-in exclusions

Every entry is a git exclude pattern, handed to git as a constant. A directory pattern (`name/`) matches a directory of that name at any depth; `.yarn/cache/` is anchored at the repository root; `*.ext` matches a file name. A negation in `.gitignore` or `.atlasignore` cannot bring back a file one of these removes.

The scope says which files an entry removes. Entries marked "tracked and untracked files" also remove tracked files, because the measurement over fifteen public repositories found no tracked source file under them. Entries marked "untracked files only" remove only untracked files that git does not ignore; a tracked file under them stays indexed. `node_modules/`, `dist/` and `build/` are untracked-only because repositories commit fixtures and ordinary code under those names, and so is every entry of a language ecosystem the measurement did not cover.

## `.atlasignore`

A repository may carry a file named `.atlasignore`, in the directory where its rules start, to leave out more.

| Aspect | Behaviour |
| --- | --- |
| Syntax | That of `.gitignore` (see the `gitignore` manual of git). Git itself evaluates the file; atlas has no matcher of its own. |
| Where | Any directory of the repository, tracked or not. A nested file applies below its own directory and overrides an outer file there, as in git. |
| Files it can remove | Tracked and untracked files alike. |
| Relation to `.gitignore` | Evaluated apart and intersected with git's own list, so it can only remove files. It cannot bring back a file `.gitignore` or `.git/info/exclude` hides. |
| Negation (`!`) | Brings back a file the same file removed earlier. It cannot bring back a built-in exclusion or a file git ignores. |
| Size | At most 64 KiB in total, over all the `.atlasignore` files of the worktree. |
| Text | Valid UTF-8 without a NUL byte. A byte order mark and CRLF line endings are fine. |
| Kind | A regular file inside the repository. A link is never followed; a link or submodule entry in the index, or a directory named `.atlasignore`, makes the file unusable. |
| Not usable | If any `.atlasignore` fails one of the rules above, none is used in that run: nothing is excluded by it, the build or the answer still succeeds, and the warning `atlasignore_unusable` is reported. |
| Permissions | None. The file cannot enable a command, change a setting or turn on diagnostics. It can only leave files out. |

A change to a `.atlasignore` takes effect for watcher events at once and for the files already indexed at the next Reconcile or `gsd-atlas build`.

## Notes and counts

The index reports what it left out as counts, never as names. A build lists the notes in its `diagnostics`; `gsd-atlas health` and the `atlas_status` tool report the numbers of the last Reconcile as `indexer.excluded`.

| Code | Severity | Text |
| --- | --- | --- |
| `index_excluded_by_defaults` | info | `N files were left out of the index by the built-in tooling and build-output exclusions` (`1 file was left out ...` for one). |
| `index_excluded_by_atlasignore` | info | `N files were left out of the index by .atlasignore` (`1 file was left out ...` for one). |
| `atlasignore_unusable` | warning | `a .atlasignore file was not used: it is larger than 64 KiB in total, is not valid text, or is not a regular file` |

A note appears only when its count is above zero, and carries no file name, pattern or repository text. A file that both a built-in entry and `.atlasignore` would remove is counted under the built-in entries. `indexer.excluded` is `{ "byDefaults": N, "byAtlasignore": N }`, or `null` before a Reconcile has run. The counts add no health reason and no degraded code.

## What is not affected

- Reading the text of a file for a citation, and listing the ADR directories, ignore the exclusions.
- The TypeScript compiler builds its program with its own file walk and resolves types from `node_modules` and the workspace as before.
- `gsd-atlas history` lists the files of a commit from git objects and does not apply the exclusions.
