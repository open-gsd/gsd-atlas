## Method

- **Questions.** The same eight gsd-core questions, [scan-questions.md](scan-questions.md), asked once per tool in the order s-001 to s-008. They were drafted from gsd-core source and ADRs without any code-intelligence tool, they are disjoint from the scored eval set, and each carries an answer key computed by the independent oracle of plan 03-04.
- **Model.** The same model alias for every tool (`sonnet`); each run file records the model id the program reported (`claude-sonnet-5-5` for codegraph) and the Claude Code version (2.1.302).
- **Isolation.** Headless `claude -p` with `--setting-sources ""` (no user, project or local settings, so none of this machine's own code-intelligence guards or servers load), `--strict-mcp-config` naming only the tool under test, no other plugin, `--tools Bash,Read`, and read-only shell patterns allowed (`git grep`, `git ls-files`, `rg`, `grep`, `ls`, `cat`, `head`, `tail`, `wc`). Every tool gets exactly these plus its own tools; the init event of each session is recorded.
- **Checkout.** A throwaway checkout of the pinned commit, outside the repository, one copy per tool. Nothing here ran against a checkout the user works in.
- **Budget.** The approved `scan.maxBudgetUsdPerSession` (3 USD) and `scan.sessionWallClockMs` (900000 ms) from the approved constants file apply to every session; a session that reaches either is recorded as such and not retried.
- **Answer and marking.** The final message ends with one JSON block of `{file, line?, symbol?}` items or an abstention. Marking is file-level against the oracle's key: `yes` (every key file and nothing else), `partial` (some), `no` (none, no parseable answer, or an answer where the key abstains). This is a scan-only check, not the eval scorer.
- **What is recorded.** Per session: status, marking, the four token fields and their sum, tool calls by name, wall time, cost, the init tool list and a short gap note. No transcript and no repository text is committed.
- **What is not claimed.** One run per question; model output varies, so a rerun need not match. The numbers say what happened in one session, not which tool is better.

## Desk review

Sources are named with the date read (2026-10-18). Claims marked Observed come from the live run or the tool's own CLI on the throwaway checkout; claims marked Desk come from the source.

### mcp-language-server and Serena

- mcp-language-server (isaacphi, Go, BSD-style license): "runs and exposes a language server to LLMs"; tools `definition`, `references`, `diagnostics`, `hover`, `rename_symbol`, `edit_file`; setup is `go install github.com/isaacphi/mcp-language-server@latest` plus a language server and a client entry with `--workspace` and `--lsp`; the README calls it beta software; GitHub shows release v0.1.1 on 2025-05-16 and the last commit on 2025-06-03. Source: https://github.com/isaacphi/mcp-language-server (README, releases, commits via the public API).
- Serena (oraios): symbol-level retrieval, editing and refactoring over MCP; language-server backend by default (40+ languages) or a paid JetBrains plugin; retrieval tools find symbol, symbol overview, find referencing symbols; type hierarchy and some refactorings are JetBrains-only; find implementations is "limited by the language server"; "agent-first tool design" that avoids "low-level concepts like line numbers"; installed with `uv tool install -p 3.13 serena-agent`, license GPL-3.0-or-later for the application and MIT for SolidLSP; user data in `~/.serena` unless `SERENA_HOME` is set; the README warns against installing through an MCP or plugin marketplace. Sources: https://github.com/oraios/serena, https://oraios.github.io/serena/02-usage/050_configuration.html, https://pypi.org/project/serena-agent/ (2.0.0, requires Python 3.11 to 3.14).

### Aider repo-map

- A concise map of the git repository listing "the most important classes and functions along with their types and call signatures", sent to the model with each request; files are graph nodes with dependency edges, ranked to fit a token budget set by `--map-tokens` (default 1k, expanded when no files are in the chat); `--show-repo-map` prints it. It supplies orientation, not answers to caller or implementer questions. Sources: https://aider.chat/docs/repomap.html, https://aider.chat/docs/config/options.html, https://pypi.org/project/aider-chat/ (0.86.2, requires Python 3.10 to 3.12).

### colbymchenry/codegraph

- MIT-licensed local code graph: a SQLite database of symbols and edges, parsed by a native kernel for 20 languages, served over MCP as `codegraph_explore` (`codegraph serve --mcp`), kept fresh by a file watcher, stated as "100% local" with a separate opt-out anonymous usage telemetry. Source: https://github.com/colbymchenry/codegraph (README), `codegraph --help` and `codegraph telemetry status` on 1.6.2.
- Observed on the pinned checkout: see the table row and `scan-runs/codegraph.json`. The tool's own `callers` command for the function in s-001 reports two definitions with only `.cts` callers; an `explore` query "which files cite ADR-58" returns symbols from `scripts/gen-adr-index.cjs` and `src/adr-parser.cts`, not the citing files. While reading, a result headed "from a different git worktree" appeared when the CLI was run in a linked worktree without its own index.

### Claude Code LSP plugin

- Code intelligence plugins connect Claude Code to a language server over LSP; the plugin "doesn't include the language server", only the command and file extensions; the official `typescript-lsp` plugin needs `typescript-language-server`; a language without an official plugin is connected by a plugin with an `.lsp.json`, loaded with `--plugin-dir`. Sources: https://code.claude.com/docs/en/plugins/code-intelligence, https://code.claude.com/docs/en/plugins-reference (LSP servers fields: `command`, `args`, `extensionToLanguage`, `startupTimeout`, `requestTimeout`, `restartOnCrash`).

### Memtrace

- Desk-only. Paid; its monthly quota is exhausted, so nothing was installed or called. The capability list and the worktree caveat in the table come from the text of this machine's CodeGraph-first routing guard, which names the Memtrace tools and says that only `find_code` accepts a `worktree` argument. No Memtrace documentation page was fetched.

## Gap summary

The scan has one tool end to end so far, so this summary is partial and will be completed when the other rows are final. Nothing here ranks the tools.

Codegraph answered seven of the eight questions fully and one partly, with a small number of tool calls on the questions that name a symbol (definition, heritage, abstention). Where the answer depends on the `.cts` to `.cjs` emit mapping, on ADR citations in comments, or on more than one hop of callers, the session fell back to shell text search, and the tool's own caller listing did not include the `.cjs` and `.js` callers. It keeps a separate index per worktree and warns when a result comes from another worktree's index, but no per-result degraded state was seen, and its output cites symbols with `file:line` only for definitions and direct callers.

The other four rows are pending the install decision.
